# 悬浮录屏工具

面向 3D 游戏数据采集的 Windows 64 位录屏工具。启动时选择保存目录，
工具自动录制鼠标指针所在的完整显示器，随后通过桌面悬浮按钮控制录制。

## 使用方法

1. 把鼠标放在需要录制的显示器上，双击 `悬浮录屏工具.exe`（源码运行可使用
   `启动录屏工具.bat`）。工具不会弹出区域选择框，
   会自动录制该显示器的完整画面；单显示器时直接录制当前屏幕。显示器实际
   分辨率必须不低于 1920×1080。
2. 在程序自带的“录屏设置”窗口中同时选择录屏保存路径，并填写每个视频
   切片的时长；允许范围为 60–900 秒，默认 60 秒。
3. 填写游戏名称，在表格中按当前游戏修改 Keymap。可以点击“从游戏目录获取”
   扫描游戏配置，也可以直接增删映射、使用 WASD/方向键模板，或导入、导出
   Keymap JSON。**动作语义必须全部改为中文**；按键名（例如 W、F1、Space）、
   设备类型和移动方向不需要翻译。工具不联网，也未内置会增大单文件 EXE 且可能
   误译游戏短语的机器翻译模型。自动扫描或导入后如仍有英文动作名称，需逐项手动
   翻译；点击“确定”时会检查动作语义，发现英文字母或没有中文内容就会定位首项、
   弹出提示并阻止进入下一步。

   自动扫描目前按“玩家配置 → 引擎/框架 → 保守通用格式 → PDF
   手册”依次识别，主要覆盖：

   - Unreal Engine 旧输入系统 INI（含玩家 `Input.ini` 和组合键），以及严格有界的
     Unreal GVAS 玩家选项存档：工具会从 `<Project>/Binaries` 等标准目录拓扑推导
     项目标识，再检查对应 `Saved/SaveGames/UserOption.sav`；若存档已经生成但尚无
     `KeyConfigSettings`，会明确说明“实际游玩或正常退出不会自动复制游戏的内置
     默认键位表”，不再误报为“游戏从未启动”。可以尝试在游戏内真正改动并保存
     一个键位后重试，但游戏是否写出完整映射仍以其实际保存行为为准。GVAS 键位
     仅在属性类型、集合边界和
     `MainKey/SecondaryKey` 结构都能完整验证时导入，未知布局会整份拒绝；
     Unity Input System 的 `.inputactions`、
     Addressables/序列化 InputActionAsset，以及文本或二进制 `InputManager`；
     Godot 3/4 的文本 InputMap 与官方 Windows `user://` 目录；.NET/MonoGame/XNA
     的 XML 玩家配置和程序集默认键位；
   - Valve GoldSrc/Source 的 CFG、Steam Cloud CFG 与 `kb_act.lst`，Source 2 的
     KeyValues/KV3/VCFG，以及 id Tech/Quake/Doom/Wolfenstein 系的
     `q3config.cfg`、`DoomConfig.cfg` 等 `bind/unbind/unbindall` 配置；
   - 常见结构化 JSON（动作映射、Oxygen Not Included 稀疏改键、Terraria/
     tModLoader Profile），以及 Barotrauma、Celeste、RimWorld 和严格通用结构的
     XML 键位表；
   - Ren'Py `config.keymap`、LÖVE/Lua 明文字面量表、RPG Maker/NW.js
     `Input.keyMapper`、GameMaker `vk_*` 和保守的 JS/JSON-like 键位对象；
   - Klei 玩家档案、Pixpil/MOAI GArchive/LuaJIT、TinyXML 编号键位表，以及具有
     明确 Controls/Input/Keybindings 结构的 INI、YAML、Lua 配置；
   - Crystal Dynamics/Foundation 一类把键位保存在当前用户注册表中的配置：
     工具会从 PE 可执行文件内的注册表路径和 `ButtonAction_*` 动作表识别格式，
     同时检查 32/64 位注册表视图，并将 DirectInput 扫描码还原为键盘/鼠标输入；
   - 数值型玩家键位 INI：工具会静态核对 PE 内声明的安全相对路径、动作表和
     `KEYBOARD_AND_MOUSE` 格式指纹，再读取 `LOCALAPPDATA` 中实际生成的
     `*Keys.ini`；支持 DirectInput 扫描码以及 `Shift+鼠标按钮/滚轮` 等组合键。
     若声明的玩家文件尚未生成，会提示先启动游戏、进入键位设置并正常退出；
     无论游戏使用注册表、配置文件还是云存档，只要没有验证到玩家实际键位，工具都会
     在载入安装目录或内置默认键位前弹出警告并默认不继续；完全没有检测到映射时，
     也会提示先启动游戏、进入按键设置，实际修改并应用至少一个键位后正常退出再重试。

   脚本、封包和 PE 可执行文件都只做静态解析，不执行游戏代码，也不会写入注册表；
   文件大小、嵌套层数、条目数、扫描目录数和扫描时间均有限制。玩家配置会在
   Steam 当前 `LastOwner`、AppData、LocalLow、
   Windows 已重定向的“文档”、OneDrive 和 Godot `app_userdata` 中按游戏身份查找。
   当前实时配置优先于 backup/old/archive，模组目录和模糊身份目录不能覆盖主游戏映射；
   稀疏改键会先按动作移除旧绑定和显式解绑，再叠加玩家的新绑定。

   Klei 格式通过安装目录中 `scripts.zip` 的控制常量签名识别，再匹配玩家 `profile`
   （当前兼容控制档案版本 10）。Pixpil/MOAI 通过 `packages.json` 和 `.g` 封包结构
   识别；TinyXML 编号表按 `tecla_N`、`pad_N`、`padMap_N` 解析，并可从受限菜单
   字典恢复动作语义；对于同格式官方教程中明确、连续声明的固定 F 功能键，
   也会在严格校验后并入映射。若同族字典提供官方简体/繁体中文资源，工具会先用
   英文结构锚点确认动作槽，再从相同槽读取中文语义；简中资源残留的少量完整通用
   标签只做严格等值词典替换，不做子串猜译。以上方式都不依赖写死的游戏名称。

   对注册表型键位，当前玩家注册表值始终优先。若游戏尚未运行、注册表还未生成，
   只有在可执行文件的动作编号关系与完整格式指纹均通过校验时，工具才会载入该格式
   的默认键位并明确提示；启动游戏、改键并正常退出后再次扫描，即可读取实际设置。

   无法通用解析的其他专有二进制 SaveGame、加密/压缩资源包、Godot PCK 内二进制
   InputMap 或完全自定义运行时按键逻辑仍需手动校正或导入 Keymap；工具不会为了
   “猜中”而执行游戏文件或把普通画质/音频配置当成键位表。
   如果没有找到实际玩家配置，工具还会递归查找安装目录自带的 PDF 游戏手册，
   从“控制/键位”页面的按键与动作列表提取官方默认键位；实际配置始终优先于手册默认值。
   没有检测到兼容档案或可解析配置时会弹窗提示，并保留当前表格不变。此时表格
   可能仍是通用模板，最终点击“确定”前必须明确确认已经逐项人工核对，防止把通用
   动作误当成当前游戏的实际键位写入录制 JSON；导入有效 Keymap 后无需重复确认。
4. 工具会检查 Windows 鼠标加速度。若“提高指针精确度”没有关闭，
   工具会拒绝启动录制。
5. 单击蓝色悬浮按钮开始录屏。若游戏已经位于前台且窗口在目标显示器内的
   覆盖宽度、高度均达到 70%，按钮会立即变红并开始录制；否则按钮会变为
   橙色并倒计时 10 秒。此时只需切回并最大化游戏，检测通过后会自动开始，
   不需要再次点击按钮；再次点击橙色按钮可以取消等待。
6. 再次单击按钮停止录屏。

录制过程中会按照设置的时长自动切分，文件名格式为
`游戏名_年-月-日_时-分-秒_唯一编号_001.mp4`、`_002.mp4`……。
手动停止时，
如果最后一个切片不足设置时长，该切片会被自动删除；如果整次录制
不足一个完整切片，则不会保留视频文件。

每个完整视频切片都会生成三件套：

```text
游戏名_..._001.mp4
游戏名_..._001.json
游戏名_..._001_keymap.json
```

会话还会生成一个 `游戏名_..._manifest.json`，其中记录工具/数据结构版本、
每个已验收切片的文件名及三个文件的 SHA-256。清单在每个切片提交后原子更新。

操作 JSON 顶层包含 `game_metadata`、`movement_events`、
`looking_events`、`action_events`，并额外保留 `raw_input`：

- `movement_events`：由 Keymap 中标记了 `movement_direction` 的键盘/
  鼠标输入或手柄左摇杆生成 W、B、L、R、WL 等方向，默认是 W/A/S/D；
  单个事件区间最长 30 秒；
- `looking_events`：与视频同为 30 Hz，记录 Windows Raw Input 原始
  相对位移 `dx/dy`、绝对坐标和方向；使用手柄时也记录右摇杆视角；
- `action_events`：根据启动时填写的 Keymap，把按键、鼠标和 XInput
  手柄按钮转换成动作语义；键盘修饰键与鼠标按钮/滚轮组成的组合键按事件发生时的
  实际状态匹配，不会用录制结束时的按键状态倒推；
- `raw_input`：保留鼠标原始位移；键盘、鼠标按钮、滚轮和手柄按钮只导出
  Keymap 已确认的输入及组合键物理组成，避免 Win 等系统操作污染游戏数据；
- `quality_control`：记录实际采集帧率、最大帧间隔、近黑画面的累计时长、
  占比、最长连续时长，以及连续重复帧检查结果。

`action_events` 和 `_keymap.json` 只使用启动时已经识别或由用户确认的映射，
不会再根据录制期间偶然出现的 Raw Input 自动生成“未配置语义”条目。未配置的
Win、Alt、鼠标点击等不会形成动作、不会进入交付 Keymap，也不会导致整段视频
被误判失败；游戏确实使用的键仍应先通过自动发现或手动编辑加入 Keymap。

每个视频切片关闭后会在后台立即执行 ffprobe、完整解码、质量检查、
JSON生成和校验和计算。成功后释放该切片的输入与质量统计内存，因此长时间
录制不会无限积累逐帧对象。异常退出后再次选择同一保存目录时，工具会根据
会话清单保留已提交三件套，并把无法恢复的未提交文件移到 `rejected` 目录。

输入追踪仅在录屏期间运行。键盘事件会包含实际输入的字符，录制密码
或其他敏感信息时请谨慎使用。

悬浮按钮可以用鼠标左键拖动。右键单击按钮可以打开保存目录、更换目录或退出；
录制期间右键菜单禁用。按钮自身的移动和点击不会写入游戏操作数据。

## 说明

- 工具录制启动时鼠标所在的完整显示器，屏幕中实际显示的游戏、桌面、弹窗和
  窗口切换都会被录入；找不到鼠标所在显示器时回退到主显示器。显示器分辨率
  低于 1920×1080 时拒绝录制。
- 开始录制前会用前台游戏窗口的几何尺寸做快速门禁，要求其与目标显示器的
  交集宽度和高度分别达到 70%。该检查只能避免明显的桌面/小窗口误录，不能
  自动判断游戏内 HUD、对话框等内容是否满足“干净场景区域”要求，仍需人工确认。
- 默认采用 DXGI Desktop Duplication，适合高帧率和全屏 Direct3D 游戏；
  DXGI 初始化失败时自动回退到 MSS。
- 输出为标准 H.264/MP4，帧率为 30 FPS，可由常见播放器和 FFmpeg 解码。
- 视频使用单次、严格 CBR 编码，不经过二次压缩或转码。
- 切片边界按输入帧号强制 IDR：60 秒切片固定为 1800 帧，避免硬件编码器
  关键帧提前或延后导致相邻切片时长漂移。
- 启动时自动探测 NVIDIA NVENC、Intel QSV 和 AMD AMF；硬件编码不可用时
  回退到 `libx264`。
- 编码队列按分辨率和 160 MB 内存预算动态设置为最多 8 帧（4K 为 5 帧），
  用于吸收软件编码或 Windows 调度的短暂背压；持续编码跟不上仍会由实际采集
  帧率门禁判定为不合格。
- 码率按录制分辨率自动选择：1080p 及以下为 24 Mbps，
  2560×1440 及以下为 36 Mbps，更高分辨率为 60 Mbps。
- 自动质量门禁要求实际采集帧率不低于 24 FPS，并拒绝单次采集停顿达到
  700 ms、连续近黑画面或连续重复帧达到 10 秒的录制。连续近黑画面或重复帧
  达到 3 秒但不足 10 秒时按游戏转场、加载页或静止菜单风险写入
  `quality_control.warnings`，保留切片供复核。超过 100 ms 但不足 700 ms
  的偶发调度尖峰也只写入警告，不会仅凭一次尖峰作废整段；100 ms 的硬性
  阈值只用于操作/动作与视频帧的对齐误差。
  未通过时不会保留可能被误当成合格数据的视频和 JSON。
- 使用随程序携带的 FFmpeg 8 和真正的 ffprobe 读取视频流
  `bit_rate`、编码、profile、像素格式、分辨率、帧率、时长和编码帧数，
  并在完整解码时再次核对实际解码帧数。
  解码或指标检查失败的切片会移入 `rejected`，不会删除此前合格切片。
- 启动及录制过程中会检查磁盘空间。至少保留 5 GB 或两个完整切片的
  预计空间（取较大值）；不足时安全停止并保留已经提交的数据。
- 悬浮按钮使用 Windows 原生顶层窗口句柄设置“不激活”和录制排除属性；在
  受支持的 Windows 10/11 系统上，点击不会抢走游戏焦点，按钮也不会出现在
  录制画面里。
- 当前版本录制系统画面，不录制系统声音和麦克风声音。
- 直接关闭黑色安装窗口不会影响后续使用；正常启动时不会显示控制台窗口。

## 手动运行

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe .\screen_recorder.py
```

## 打包成单文件 EXE（64 位）

双击 `打包EXE.bat`，完成后会生成：

```text
dist\悬浮录屏工具.exe
```

该 EXE 面向 64 位 Windows。对方不需要安装 Python 或项目依赖，
直接双击即可运行。
